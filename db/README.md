# db

Plain SQL migrations plus the seed pipeline. The same files run under Docker Compose, Fly.io and Aurora PostgreSQL.

## Migrations (`db/migrations`)

| File | Schema | Content |
|---|---|---|
| `0001_init.sql` | | extensions, migration ledger |
| `0002_legacy_sp_schema.sql` | `legacy` | Strategic Planner `SP_` tables, sequences, views and triggers converted by ora2pg (generated, see below) |
| `0003_legacy_sp_data.sql` | `legacy` | the sample rows the APEX app ships with (generated) |
| `0004_evs_core.sql` | `evs` | `lock_dim`, `lock_status_fact` (monthly partitions), `status_eval`, `stoppage`, `feed_health`, `srp_snapshot`, `srp_site`, `threshold`, view `evs.lock_current` |
| `0005_synth.sql` | `synth` | `program`, `p2_project`, `p2_milestone`, `cefms_work_item`, `cefms_funding`, `ems_labor_plan`, `ems_labor_log`, `cmp_contract`, `builder_component` plus roll-up views |

Apply with `cd apps/api && uv run evs migrate`. The ledger is `public.schema_migration`; files apply once, in name order.

## ora2pg conversion (`db/ora2pg`)

`run.sh` downloads the Strategic Planner archive, unwraps the APEX install scripts into Oracle DDL (`oracle/`),
runs ora2pg 25 per object type with `--estimate_cost` (`output/`), then `postprocess.py` rewrites the output into
`0002` and `0003` and writes `ASSESSMENT.md`. Do not edit `0002` or `0003` by hand; change `postprocess.py` and rerun.

ora2pg needs a live Oracle connection for `SHOW_REPORT`; file-input mode cannot produce it. `ASSESSMENT.md` lists what was
converted, the per-package cost estimate, every rewrite rule applied and the APEX objects that have no PostgreSQL equivalent.

## Seed (`db/seed`)

`cd apps/api && uv run evs seed [--reset]` loads, in order:

1. Public samples from `db/seed/data/public/`: the NDC lock GeoJSON (234 chambers collapsed to one `evs.lock_dim` row per lock),
   the three LPMS JSON feeds as one baseline `lock_status_fact` / `status_eval` set labelled `source = 'fixtures'`,
   and the Sustainable Rivers Program snapshots and sites with their source URLs.
2. Synthetic CEFMS / P2 / EMS / CMP / BUILDER rows generated by `evs_seed/synth.py` from `db/seed/data/fy26_om_jsheet.csv`
   (the FY26 Civil Works O&M budget justification project list, parsed by `jsheet.py`). The generator is deterministic
   (`SEED = 20261006`) and every row carries `source = 'synthetic'`.

`--reset` truncates `evs.*` and `synth.*` first. Without it the command is a no-op when `synth.program` already has rows,
so the Compose API command (`evs migrate && evs seed && uvicorn ...`) is safe to rerun.

`cd apps/api && uv run evs dump-fixtures` (also `make fixtures`) regenerates `apps/api/fixtures/*.json` from the seeded
database so fixture mode and database mode return the same data. `accessibility.json` is hand maintained.

## Built-in stories in the synthetic data

- Program `LRD-NAV` is over-obligated (obligations above its funded amount).
- Two P2 projects carry slipped milestones (`synth.p2_milestone.status = 'slipped'`).
- District SWT shows an overtime spike in pay periods 14 to 18.
- Olmsted Locks and Dam has the lowest BUILDER condition index.

All synthetic names, amounts and dates are illustrative. They reuse real district and business line vocabulary but describe no real project status.
