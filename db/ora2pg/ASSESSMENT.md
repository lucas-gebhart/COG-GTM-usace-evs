## Limitations and hand conversions

- File-input mode cannot read `wwv_flow_imp_shared.create_install_script` wrappers; `extract_apex_install_scripts.py` unwraps them first.
- `SHOW_REPORT` and `INSERT`/`COPY` data export require an Oracle connection. Shipped seed and sample rows are converted by regex (`sysdate`, `to_date`) in `postprocess.convert_oracle_dml` into 0003.
- `sp_util.add_setting` / `sp_util.add_ai_prompt` seed calls and the two `dbms_scheduler` jobs (`oracle/09_other_plsql.sql`) are not loaded; settings and prompts are APEX runtime configuration with no EVS equivalent, and the jobs are replaced by the ingestion worker.
- Packages call `apex_util`, `apex_mail`, `apex_string`, `dbms_lob` and `apex_json`; ora2pg converts syntax but the APEX PL/SQL API has no PostgreSQL equivalent. Each package's responsibilities are re-implemented in `apps/api/evs` (approvals, comments, summaries, notifications).
- Oracle `default on null` becomes a plain `DEFAULT`; the before-insert triggers (`*_biu`) still populate audit columns.
- APEX splits long scripts into `append_to_install_script` chunks, sometimes mid line (the Portugal row in `install_seed_countries.sql`); the extractor concatenates chunks byte for byte.
